# ไคลเอนต์แบบคำสั่ง

[ภาพรวม](../../README.th.md) · [เอกสารภาษาอังกฤษ](../en/cli.md)

ไฟล์ `ptunnel.js` ใช้เพียง Node.js **22.12 ขึ้นไป** CLI สำเร็จรูปใช้คำสั่งเดียวกัน แทน `node ptunnel.js` ด้วยชื่อไฟล์ที่ดาวน์โหลด หรือ `ptunnel` หากติดตั้งไว้ใน PATH แล้ว

```bash
node ptunnel.js
node ptunnel.js setup
node ptunnel.js http 3000
node ptunnel.js tcp 22
node ptunnel.js http 192.168.1.50:80
node ptunnel.js http localhost:3000 --domain apps.example.com
node ptunnel.js http 3000 --domain demo.example.net --root
node ptunnel.js status
node ptunnel.js reset
node ptunnel.js --help
node ptunnel.js --version
```

หากไม่ใส่อาร์กิวเมนต์ โปรแกรมตั้งค่าครั้งแรกหรือเปิดรายการล่าสุด `setup` เปลี่ยนค่าที่บันทึก จากนั้นรันไคลเอนต์เพื่อเชื่อมต่อ `status` ไม่แสดงกุญแจ ส่วน `reset` ล้างค่าหลังถอนงานเริ่มอัตโนมัติทั้งหมดแล้ว

เป้าหมายเป็นพอร์ต `host:port` หรือ URL เว็บในเครื่องที่รองรับได้ IPv6 ให้ใส่วงเล็บ เช่น `[::1]:3000` เครื่องไคลเอนต์ต้องเข้าถึงเป้าหมายได้ HTTP ส่งต่อไปเว็บ HTTP ภายใน ส่วน TCP ส่งไบต์ของบริการตามเดิม ไม่มี UDP หรือการส่งต่อ WebSocket ของแอป

`--domain` เลือกโดเมนที่ผู้ดูแลเปิดไว้ `--root` ขอใช้ชื่อโดเมนนั้นโดยตรงซึ่งต้องอนุญาตไว้ชัดเจน หากไม่เลือกจะได้ชื่อย่อย การจองชื่อผูกกับเจ้าของกุญแจและรายการ tunnel ที่คงเดิม ไม่ได้เชื่อเพียง ID ที่ไคลเอนต์ส่งมา การเปลี่ยนเป้าหมายอาจได้รายการและที่อยู่ต่างออกไป

ตั้งค่าครั้งแรกโดยไม่ใช้ตัวช่วยโต้ตอบได้ด้วย:

```bash
node ptunnel.js init --server admin.example.com --token YOUR_ACCESS_KEY
```

หากไม่ต้องการให้รหัสอยู่ในประวัติคำสั่งหรืออาร์กิวเมนต์ของโปรเซส ให้ตั้งค่าแบบโต้ตอบ ชื่อเซิร์ฟเวอร์เปลี่ยนเป็น `wss://<host>/_private-tunnel/ws` อัตโนมัติ หากผู้ดูแลเปลี่ยน path ให้ใช้ URL เต็ม `ws://` ใช้ได้เฉพาะ localhost/loopback ที่ระบุแน่นอนสำหรับพัฒนา การเชื่อมต่อระยะไกลต้องใช้ WSS

| คำสั่ง / ตัวเลือก | ทำอะไร |
| --- | --- |
| `http <target>`, `tcp <target>` | จำรายการล่าสุดและเริ่มเชื่อมต่อ |
| `--plain` | แสดงบันทึกทีละบรรทัดสำหรับเทอร์มินัลพื้นฐาน |
| `--startup` | ติดตั้งเป้าหมายนี้เป็นงานเริ่มตั้งแต่บูตด้วยค่าเซิร์ฟเวอร์ที่บันทึก |
| `--startup --dry-run` | ดูสิ่งที่จะติดตั้ง |
| `startup install [--dry-run]` | ติดตั้งจากรายการล่าสุด |
| `startup status` | แสดงงานกับ ID |
| `startup start ID` / `stop ID` | เริ่มทันทีหรือหยุดจนถึงบูตครั้งหน้า |
| `startup remove ID` / `remove all` | ถอนการเริ่มอัตโนมัติถาวร |

CLI เก็บกุญแจเป็นข้อความใน `~/.ptunnel` ใช้สิทธิ์ `0600` บน Unix เลือกไฟล์อื่นได้ด้วย `PTUNNEL_CONFIG_PATH` ป้องกันไฟล์และสำเนาสำรองให้ดี แอปเดสก์ท็อปใช้ไฟล์ของตัวเองกับที่เก็บรหัสของระบบ และอ่านค่าจาก CLI เดิมได้โดยไม่เขียนทับไฟล์ต้นทาง

เมื่อเครือข่ายหลุดจะลองใหม่โดยเว้นช่วงเพิ่มและสุ่มเวลา งาน HTTP หรือ TCP ที่ขาดไม่กลับมาทำต่อ หากกุญแจถูกปฏิเสธต้องอัปเดตรหัส Ctrl+C หยุดไคลเอนต์แบบโต้ตอบ แต่ต้องถอนงานเริ่มอัตโนมัติหากไม่ต้องการให้บริการที่ติดตั้งแล้วกลับมาในบูตถัดไป
