# เริ่มตั้งแต่บูต ก่อนล็อกอิน

[ภาพรวม](../../README.th.md) · [เอกสารภาษาอังกฤษ](../en/startup.md)

ผมใช้ตัวทำงานที่ไม่ต้องมีหน้าจอ เพื่อให้ tunnel ที่ตั้งไว้ไม่ต้องรอเปิดแอปเดสก์ท็อป กำหนดและตรวจเซิร์ฟเวอร์ กุญแจ กับเป้าหมายก่อน แล้วติดตั้งรายการที่ต้องการ:

```bash
node ptunnel.js tcp 22 --startup
node ptunnel.js http 3000 --startup --dry-run
node ptunnel.js startup install
node ptunnel.js startup status
node ptunnel.js startup stop JOB_ID
node ptunnel.js startup start JOB_ID
node ptunnel.js startup remove JOB_ID
node ptunnel.js startup remove all
```

ตัวเลือกเริ่มอัตโนมัติของแต่ละรายการในแอปติดตั้งตัวทำงานแบบเดียวกัน ระบบปฏิบัติการอาจขอสิทธิ์ผู้ดูแลตอนติดตั้ง บูตครั้งถัดไปรันได้โดยไม่เปิดหน้าจอและลองเชื่อมใหม่เมื่อเครือข่ายพร้อม ต้องตั้งเว็บ SSH หรือเกมให้เริ่มเองด้วย PrivateTunnel ไม่ได้เปิดโปรแกรมปลายทางให้

| ระบบ | วิธีติดตั้ง | พฤติกรรมสำคัญ |
| --- | --- | --- |
| Windows | งานตามกำหนดเวลาที่เริ่มตอนบูต | ใช้ LocalService กับไฟล์ค่าและ runtime ที่จำกัดสิทธิ์ ไม่รอล็อกอิน |
| Linux | บริการ systemd ระดับระบบ | ใช้ผู้ใช้ที่ติดตั้งและจำกัดสิทธิ์ ต้องมี systemd จริง |
| macOS | LaunchDaemon | ใช้ผู้ใช้ที่ติดตั้ง เริ่มก่อนเข้าหน้าเดสก์ท็อป |
| Termux | สคริปต์ใน `~/.termux/boot` | ต้องติดตั้ง Termux:Boot จากแหล่งที่เข้ากัน เปิดส่วนเสริมหนึ่งครั้ง และอนุญาตเบื้องหลัง |

Android ไม่เหมือนบริการบูตบนคอม การปลดล็อกพื้นที่เก็บข้อมูล ระบบประหยัดพลังงานของผู้ผลิต และข้อจำกัด Android อาจทำให้เริ่มช้าหรือหยุด จึงไม่รับประกันว่ามือถือทุกรุ่นจะเริ่มได้ก่อนปลดล็อก

แต่ละงานเก็บ **สำเนาค่า ณ ตอนติดตั้ง** ได้แก่เซิร์ฟเวอร์ กุญแจ เป้าหมาย ตัวตนรายการ และการเผยแพร่ ต้องมีสำเนานี้เพราะงานก่อนล็อกอินใช้ที่เก็บรหัสเดสก์ท็อปที่ยังล็อกอยู่ไม่ได้ Unix ใช้สิทธิ์ส่วนตัว Windows จำกัด ACL กุญแจในไฟล์ที่ป้องกันสิทธิ์นี้เป็นข้อความธรรมดา การเลือกติดตั้งเริ่มอัตโนมัติจึงเป็นการยอมให้เก็บรหัสเพิ่มสำหรับบริการนั้น

เปิด startup ขณะแชร์อยู่จะสลับตัวทำงานและตัด TCP เดิมหนึ่งครั้ง ให้เชื่อมใหม่หลังติดตั้งโดยใช้ที่อยู่ล่าสุด หลังอัปเดตไคลเอนต์ต้องติดตั้งงานบูตใหม่ด้วย มิฉะนั้นสำเนาที่ป้องกันไว้ยังอาจรันไคลเอนต์เก่าซึ่งมีพฤติกรรม timeout เดิม

ดู ID และตำแหน่งไฟล์จากผลติดตั้งหรือสถานะเพื่อตรวจบริการกับบันทึก บันทึกหมุนเมื่อประมาณ 1 MiB เก็บสำรองหนึ่งชุด heartbeat ของตัวทำงานอัปเดตทุกสามวินาที และถือว่าเก่าเมื่อเกินสิบห้าวินาที สถานะไม่ได้ยืนยันไฟร์วอลล์สาธารณะ ระบบป้องกันตัวทำงานซ้ำตรวจตัวตนโปรเซสที่ถือ lock ก่อนตัดสินว่าอีกตัวกำลังรัน

`stop` หยุดชั่วคราว บูตถัดไปเริ่มอีก ส่วน `remove` ถอนการเริ่มถาวร การแก้โปรไฟล์ CLI ไม่ได้เปลี่ยนสำเนาของงานเก่า ต้องถอนแล้วติดตั้งใหม่หลังเปลี่ยนกุญแจ เป้าหมาย หรือ runtime อย่าย้าย Node หรือไฟล์รันบน Linux/macOS โดยไม่อัปเดตงาน Windows คัดลอก runtime ไปไว้ในตำแหน่งบริการที่จำกัดสิทธิ์

ส่วนนี้ติดตั้งการเริ่มอัตโนมัติของ **ไคลเอนต์** ไม่ได้ติดตั้งเซิร์ฟเวอร์สาธารณะเป็นบริการ Windows ดู[คู่มือเซิร์ฟเวอร์](server.md) สำหรับการดูแลโปรเซสฝั่งเซิร์ฟเวอร์
