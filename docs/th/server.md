# ติดตั้งเซิร์ฟเวอร์

[ภาพรวม](../../README.th.md) · [เอกสารภาษาอังกฤษ](../en/server.md)

เซิร์ฟเวอร์เป็นทางเข้าจากอินเทอร์เน็ต ไคลเอนต์เปิด WSS ออกมาแล้วเซิร์ฟเวอร์ส่งคำขอผู้ชมกลับผ่านเส้นทางนั้น ผมแยกชื่อแอดมินกับชื่อเว็บที่เผยแพร่ เพื่อไม่ให้เส้นทางของเว็บที่แชร์กลายเป็นหน้าแอดมิน

## เตรียมและเริ่มครั้งแรก

ใช้ Node.js **22.12 ขึ้นไป** ที่เก็บข้อมูลถาวรที่เขียนได้ IP/DNS สาธารณะ และ reverse proxy ในเครื่องเดียวกัน SQLite เป็นค่าเริ่มต้น เลือก MySQL ได้ ติดตั้ง dependency บนระบบจริง อย่าคัดลอก `node_modules` ที่มีส่วนเนทีฟข้ามระบบปฏิบัติการ

```bash
git clone https://github.com/Jindanet/private-tunnel.git
cd private-tunnel
npm ci --omit=dev
cp .env.example .env
```

แก้โดเมน ที่เก็บข้อมูล และรหัส MySQL หากใช้ใน `.env` คง listener ภายในไว้ที่ `127.0.0.1` เมื่อ Nginx อยู่เครื่องเดียวกัน จากนั้นใช้ `npm run server` เพื่อตั้งค่าครั้งแรก หรือติดตั้งบริการดูแลโปรเซสตามด้านล่าง ไม่ต้องรันเซิร์ฟเวอร์ด้วย root เพื่อจัดการไฟร์วอลล์

หากยังไม่มีรหัสแอดมิน ระบบสร้าง `DATA_DIR/admin-bootstrap.txt` ด้วยสิทธิ์ส่วนตัว อ่านในเครื่องแล้วลงชื่อเข้าใช้ เปลี่ยนรหัสทันที ระบบลบไฟล์เริ่มต้นและยกเลิกเซสชันเก่า รหัสในฐานข้อมูลเดิมมีลำดับเหนือ `DASHBOARD_PASSWORD` โดเมนจากสภาพแวดล้อมใช้เริ่มครั้งแรก หลังจากนั้นแก้ผ่านหน้าแอดมิน

## DNS และ HTTPS

ตัวอย่างระเบียนที่ชี้มาที่เซิร์ฟเวอร์:

```text
admin.example.com         A/AAAA → IP เซิร์ฟเวอร์
*.apps.example.com       A/AAAA → IP เซิร์ฟเวอร์
apps.example.com         A/AAAA → IP เซิร์ฟเวอร์ ถ้าใช้ชื่อหลักเผยแพร่ด้วย
```

เพิ่ม AAAA เฉพาะเมื่อ IPv6 ใช้งานได้จริง ขอใบรับรองสำหรับชื่อแอดมิน ชื่อ wildcard และชื่อหลักที่ต้องเผยแพร่ ใบรับรอง wildcard ไม่ครอบคลุมชื่อแม่แบบไม่มีชื่อย่อย การออก wildcard ด้วย ACME ต้องตรวจผ่าน DNS ตั้งต่ออายุและโหลด reverse proxy ใหม่ตามเครื่องมือที่ผู้ให้บริการรองรับ [การตรวจ DNS ของ Let's Encrypt](https://letsencrypt.org/docs/challenge-types/#dns-01-challenge)

ตั้งโดเมนเผยแพร่ในแอดมินแล้วใช้ Nginx ที่ระบบสร้างให้ หรือปรับ [`deploy/nginx.example.conf`](../../deploy/nginx.example.conf) แทนชื่อ พาธใบรับรอง และพอร์ตตัวอย่างทั้งหมด มีขั้นตอน Linux, Docker และ Windows เพิ่มใน[คู่มือติดตั้งระบบฉบับละเอียด](../../deploy/README.md)

| บริการภายใน | ค่าเริ่มต้น | เส้นทางภายนอก |
| --- | --- | --- |
| WebSocket ไคลเอนต์ | `127.0.0.1:8080` | ชื่อแอดมิน `/_private-tunnel/ws` อุปกรณ์ใช้ที่เดียวกันแต่ subprotocol แยก |
| แอดมิน | `127.0.0.1:8081` | ชื่อแอดมินแบบตรงตัว `/_private-tunnel/admin` |
| HTTP ที่เผยแพร่ | `127.0.0.1:8082` | ชื่อที่อนุญาตให้เผยแพร่ |

ให้ Nginx เขียน forwarded header ทับ เชื่อถือ header นี้เฉพาะการเชื่อมจาก loopback อย่าเปิดพอร์ตภายในสู่อินเทอร์เน็ตหรือเปลี่ยน container เป็น bridge โดยยังไม่มีขอบเขต proxy ที่ชัดเจน ทุกชื่อเผยแพร่ต้องปฏิเสธ **control root แบบตรงตัวและลูกทั้งหมด** รวม `/_private-tunnel` แม้ไม่มี tunnel ส่วน `/api` ของแอปใช้ได้ตามปกติ ยังไม่รองรับ WebSocket upgrade ของแอป

ตรวจไวยากรณ์ Nginx โหลดค่าใหม่ แล้วทดสอบหน้าแอดมินบนชื่อที่ถูก และ 404 เมื่อเรียกบนชื่อเผยแพร่ ห้ามเผยแพร่ชื่อแอดมินเองเป็นเว็บแบบชื่อหลัก หากเปลี่ยน control root ต้องอัปเดตทั้ง Nginx กับ URL ของไคลเอนต์

## ให้ทำงานต่อเนื่อง

เทมเพลต [`deploy/private-tunnel.service`](../../deploy/private-tunnel.service) ใช้บัญชี `privatetunnel` ที่ไม่มีสิทธิ์ผู้ดูแล เก็บโค้ดใน `/opt/private-tunnel` สภาพแวดล้อมส่วนตัวใน `/etc/private-tunnel/server.env` และข้อมูลที่เขียนได้ใน `/var/lib/private-tunnel` ทำตาม[คำสั่งติดตั้งครบชุด](../../deploy/README.md#3-linux-service-with-systemd) รวมที่เก็บข้อมูลแบบ absolute และเจ้าของไฟล์ ตรวจตำแหน่ง Node ให้ตรงเครื่อง

[`compose.yaml`](../../compose.yaml) ใช้ **host networking บน Linux** พร้อม volume ถาวรและจำกัดสิทธิ์ container volume ใหม่ไม่ย้ายฐานข้อมูลเก่าจากเครื่องให้เอง อย่าลบ volume เพื่ออัปเดตธรรมดา Windows ต้องตั้งตัวดูแลโปรเซสหรือบริการเซิร์ฟเวอร์แยก ส่วน `--startup` ของไคลเอนต์ไม่ได้ติดตั้งเซิร์ฟเวอร์

`/healthz` บน listener แอดมินภายในตรวจว่าโปรเซสยังอยู่ ไม่ได้ยืนยัน DNS ใบรับรอง ไฟร์วอลล์ TCP หรือ tunnel รายใด ต้องทดสอบจากอีกเครือข่ายด้วย

## TCP และไฟร์วอลล์

`TCP_ALLOWED_PORTS=30000-40000` กำหนดพอร์ตที่แจกได้ ต้องเปิดช่วงนี้ในไฟร์วอลล์เครื่อง คลาวด์ และ NAT ก่อน ระบบข้ามพอร์ตที่ถูกใช้ ถูกจอง หรือไม่อนุญาต และถือ listener ที่เลือกไว้ต่อเนื่อง

หากต้องใช้พอร์ตสำรอง ให้เปิดก่อนแล้วเพิ่มในกติกา ลำดับเลือกคือ **30000–40000**, **40001–65535**, แล้ว **1024–29999** เฉพาะพอร์ตที่ประกาศไว้ หากเต็มจะสร้างไม่สำเร็จ ไม่เลือกพอร์ตศูนย์หรือพอร์ตที่ต้องใช้สิทธิ์สูงเอง `TCP_PORT_MIN`/`TCP_PORT_MAX` เดิมไม่ควบคุมกติกานี้

คง `AUTO_FIREWALL=false` และจัดไฟร์วอลล์แยก โปรแกรมตรวจไม่ได้ว่าไฟร์วอลล์คลาวด์หรือ NAT เปิดแล้ว `TCP_VISITOR_ALLOWLIST` จำกัด IP/CIDR ของผู้ชมจาก socket จริง ไม่เชื่อ forwarded header ของผู้ใช้ TCP สาธารณะไม่มี TLS หรือยืนยันผู้ชมอัตโนมัติ บริการปลายทางต้องมีเองเมื่อจำเป็น

## กุญแจ ข้อมูล และสำรอง

สร้างกุญแจแยกรายการในหน้าตั้งค่า กุญแจเดสก์ท็อปกับอุปกรณ์เป็นคนละประเภท อุปกรณ์แสดงรหัสผ่านเข้าชมอีกชุด การเปลี่ยนรหัสเปลี่ยนทั้งสองและตัดการเชื่อมต่อ การเปลี่ยนรหัสเดิมรักษาความเป็นเจ้าของ ส่วนการออกกุญแจใหม่ทั้งหมดสร้างเจ้าของใหม่

สำรองฐานข้อมูล `.env` หรือไฟล์สภาพแวดล้อมของบริการ **`DATA_DIR/client-keys.json`** และค่าระบบใบรับรองกับ proxy ตามนโยบายของคุณ registry เก็บแฮชแต่ ID จำเป็นต่อการรักษาเจ้าของชื่อ ห้ามแก้ขณะเซิร์ฟเวอร์รันหรือ commit ลง Git

SQLite ให้หยุดบริการก่อนคัดลอก หรือใช้วิธีสำรองออนไลน์ที่ถูกต้อง การคัดลอกเฉพาะไฟล์หลักระหว่างเขียน WAL อาจสูญเสียข้อมูลที่บันทึกแล้ว ทดลองกู้ในสภาพแวดล้อมแยก ตรวจรหัส ชื่อที่จอง แอดมิน และสิทธิ์เก็บไฟล์ ระบบ mirror ไม่ใช่สำรองข้อมูลหรือสลับระบบล้มเหลวอัตโนมัติ
