# พัฒนาและออกรุ่นใหม่

[ภาพรวม](../../README.th.md) · [เอกสารภาษาอังกฤษ](../en/development.md)

## โครงสร้างซอร์ส

| ที่อยู่ | หน้าที่ |
| --- | --- |
| `app/` | โปรเซสหลัก Electron การสื่อสารภายใน ที่เก็บรหัส และหน้าจอ |
| `client/` | CLI การส่งต่อ HTTP/TCP และงานเริ่มอัตโนมัติ |
| `ptunnel.js` | CLI ไฟล์เดียวที่สร้างจากซอร์ส รวม WebSocket กับใบอนุญาต |
| `server/` | listener หน้าแอดมิน ฐานข้อมูล ยืนยันตัวตน และจัดเส้นทาง |
| `server/device-bridge.js` | ตัวแปลงโปรโตคอลอุปกรณ์ที่สร้างโดยเซิร์ฟเวอร์ |
| `shared/protocol.js`, `shared/tunnel-v4.js` | ส่วนควบคุมเดสก์ท็อปกับโปรโตคอลควบคุมสิทธิ์รับข้อมูลปัจจุบัน |
| `shared/device-protocol.js` | ค่าคงที่และตรวจรูปแบบข้อความอุปกรณ์ |
| `device/PrivateTunnelDevice/` | ไลบรารี Arduino ตัวอ่าน WebSocket แบบจำกัดขนาด และสองตัวอย่าง |
| `tests/` | ทดสอบย่อย gateway Electron เริ่มอัตโนมัติ และตัวอ่านเฟิร์มแวร์ |
| `deploy/`, `.github/` | ตัวอย่างบริการ/proxy และระบบทดสอบ/เผยแพร่ |

## พัฒนาแอป

ใช้ Node.js **22.12 ขึ้นไป** และ dependency ตาม lockfile:

```bash
npm ci
npm run app
npm test
```

เป็นคำสั่งสำหรับสภาพแวดล้อมที่อนุญาตให้รัน **`npm test` เปิด Electron และเซิร์ฟเวอร์ทดสอบภายในจริง** ไม่ใช่การตรวจไฟล์อย่างเดียว การอัปเดตครั้งนี้รันการทดสอบและคอมไพล์ผ่าน GitHub Actions แทนเครื่องผู้ดูแล

การทดสอบใช้ข้อมูลชั่วคราวกับ loopback CI ใช้ Windows/Linux และ Node 22/24 มีจอเสมือนบน Linux ตรวจความใหม่ของไฟล์เดี่ยวและตรวจ dependency ฝั่งใช้งาน การทดสอบ MySQL ต้องกำหนดฐานข้อมูลทดสอบโดยตั้งใจ ห้ามชี้ไปข้อมูลใช้งานจริง

เมื่อเปลี่ยนซอร์สไคลเอนต์หรือ metadata ที่ถูกรวม ให้สร้างไฟล์เดี่ยวใหม่ในสภาพแวดล้อมพัฒนาหรือ CI ที่อนุญาต:

```bash
npm run build:termux
npm run check:termux
```

ระบบตรวจเปรียบเทียบผลสร้างกับไฟล์ใน Git และตรวจว่าไม่มี dependency ภายนอกเหลืออยู่ขณะรัน ปกติให้แก้ซอร์ส ไม่แก้ไฟล์ที่สร้างแล้วเป็นวิธีหลัก

## คอมไพล์เฟิร์มแวร์

ไม่ต้องใช้ไลบรารี WebSocket เพิ่ม CI ตรึง Arduino CLI **1.5.1**, core ESP32 **3.3.12** และ ESP8266 **3.1.2** คอมไพล์ `BasicHttp` กับ `ProvisionedHttp` ทั้งคู่ ตัวอย่างคำสั่งเมื่อมี core ที่ตรงแล้ว:

```bash
arduino-cli compile --fqbn esp32:esp32:esp32 --library device/PrivateTunnelDevice device/PrivateTunnelDevice/examples/ProvisionedHttp
arduino-cli compile --fqbn esp8266:esp8266:nodemcuv2 --library device/PrivateTunnelDevice device/PrivateTunnelDevice/examples/ProvisionedHttp
```

การทดสอบ C++ ตรวจไบต์ตัวอย่างร่วม อ่านทีละไบต์ body คำขอ สิทธิ์ส่งคำตอบ ยกเลิกงาน ปิดเมื่อรหัสถูกปฏิเสธ ปฏิเสธ frame เกิน และ heartbeat หมดเวลา ตัวจำลองเครือข่าย Arduino **ไม่ได้ทดสอบการเข้ารหัส การตรวจ TLS จริง Wi-Fi หรือเวลาบนฮาร์ดแวร์** ส่วน gateway จริงตรวจแยกประเภทกุญแจ ผู้ชม อัปโหลด 1 KiB คำตอบยาว งานเกิน ยกเลิก และเปลี่ยนกุญแจ

การวัดบอร์ดจริงยังต้องทำเพิ่ม ดู[แนวทางวัดในคู่มืออุปกรณ์](devices.md) artifact เฟิร์มแวร์เป็นผลคอมไพล์ตามเป้าหมายที่ระบุ ไม่ใช่ไฟล์เดียวที่ตั้งค่าครบให้ทุกบอร์ด ผู้ใช้ยังต้องมีเซิร์ฟเวอร์ กุญแจ และ CA ของตัวเอง

## สร้างและเผยแพร่

แพ็กเกจมีสคริปต์สร้าง CLI แต่ละระบบกับ Electron Builder เผยแพร่ GUI Windows แบบ ZIP เป็นหลัก Linux/macOS สร้าง GUI จากซอร์สได้ การแพ็กไม่ได้ลงลายเซ็นหรือติดตั้งอัปเดตอัตโนมัติให้

ระบบเผยแพร่เริ่มเมื่อ push `main` แท็กรุ่นที่ตรง หรือสั่งเอง ตรวจรุ่น package/lockfile ปฏิเสธแท็กที่ถูกย้ายหรือการถอยรุ่น และข้ามรุ่นที่เผยแพร่แล้ว หากต้องการไฟล์สาธารณะใหม่ต้องเพิ่ม **เลขรุ่นแพ็กเกจใหม่**

ก่อนเผยแพร่จะทดสอบซอร์ส ตรวจไฟล์เดี่ยว สร้างแอป/CLI Windows, CLI Linux และ macOS ทั้งสองสถาปัตยกรรม รวมถึงคอมไพล์และทดสอบไลบรารีอุปกรณ์ ขั้นตอนซอร์สสร้าง ZIP ไลบรารีที่ติดตั้งผ่าน Arduino ได้ด้วย รอทุกงานที่จำเป็น ตรวจชุดไฟล์ครบ และเขียน `SHA256SUMS.txt` ก่อนแสดงรุ่นให้ดาวน์โหลด หากอัปโหลดล้มเหลวคงเป็นฉบับร่างและทำต่อได้โดยไม่แทนรุ่นที่เผยแพร่แล้ว

ใช้ `deploy/RELEASE-x.y.z.md` อธิบายสิ่งที่ผู้ใช้ได้รับ อัปเดตประวัติและคู่มือสองภาษา ระบุข้อจำกัดตามจริง ห้ามรวม `.env` ฐานข้อมูลส่วนตัว registry กุญแจ ข้อมูล EEPROM หรือภาพที่มีรหัสจริงลง commit หรือ artifact
