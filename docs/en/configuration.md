# Configuration and upgrades

[Overview](../../README.md) · [Thai guide](../th/configuration.md) · [Complete environment template](../../.env.example)

Environment variables configure listeners, storage and operational policy. Domains, the legacy shared key and administrator credentials are seeded into the database on first boot; the administrator UI owns stored settings afterward. Changing `.env` is not a way to overwrite an existing administrator password or publish-domain list. Restart after changing listener or storage configuration.

| Variable | Default / meaning |
| --- | --- |
| `PRIMARY_DOMAIN`, `TUNNEL_DOMAIN` | First-boot administrator hostname and publish-domain seed |
| `INTERNAL_HOST` | `127.0.0.1`; keep internal listeners private |
| `WS_PORT`, `DASHBOARD_PORT`, `PROXY_PORT` | `8080`, `8081`, `8082` |
| `DASHBOARD_PASSWORD` | First-boot only when no current/legacy password exists; empty generates a private bootstrap file |
| `TUNNEL_TOKEN` | Legacy shared key, unused for normal individual-key authentication |
| `ALLOW_SHARED_TUNNEL_TOKEN` | `false`; enables legacy shared-owner compatibility |
| `ALLOW_UNAUTHENTICATED_TUNNELS`, `ALLOW_LEGACY_QUERY_TOKEN` | `false`; retain secure defaults on networked servers |
| `REQUIRE_DATA_TRANSPORT_V4` | `true`; desktop transport requirement; trusted device adapter stays separate |
| `HTTP_IDLE_TIMEOUT_MS` | `30000`; per-request inactivity, integer 50–3600000, refreshed by progress |
| `TCP_ALLOWED_PORTS` | `30000-40000`; declared preopened allocation policy |
| `TCP_BIND_HOST` | Empty uses OS interface defaults; otherwise a local IP |
| `TCP_VISITOR_ALLOWLIST` | Empty permits all; comma-separated IPs/CIDRs restrict real TCP peers |
| `TCP_IDLE_TIMEOUT_MS` | `0`; no application-data idle expiry. Optional integer 1–2147483647 sets a server-side limit in milliseconds; restart after changing |
| `AUTO_FIREWALL` | `false`; legacy local-rule management does not verify external reachability |
| `REQUEST_LOGGING` | `true`; false disables new request metadata, not existing rows/backups |
| `DATA_DIR` | `./data`; private writable state and key registry |
| `DB_PROVIDER` | `sqlite`; optional `mysql` |
| `SQLITE_PATH` | Explicit SQLite path takes priority over `DATA_DIR`; otherwise `DATA_DIR/tunnel.db` |
| `DB_PATH` | Legacy SQLite path alias |
| `MYSQL_HOST`, `MYSQL_PORT` | `127.0.0.1`, `3306` |
| `MYSQL_USER`, `MYSQL_PASSWORD`, `MYSQL_DATABASE` | Dedicated DB account and database; see template |
| `DB_SYNC_TARGETS` | Empty; optional migration mirrors are not backup/failover |
| `DB_SYNC_STRICT` | `true`; mirror failures fail the operation, without cross-database atomicity |
| `DB_BOOTSTRAP_SYNC` | `false`; only enable for a planned, backed-up migration to an empty target |
| `NODE_ENV=production` | Rejects non-primary mirror targets; use one authoritative database |

The example sets both `DATA_DIR` and `SQLITE_PATH`; update both when moving state. MySQL initialization may create a database when the account has permission; otherwise provision it beforehand and grant the needed schema/data privileges. A service account must be able to write its own state without granting write access to the application source tree.

Stored Settings include primary/publish domains, whether each domain permits subdomain or exact-root publishing, TCP address choices and the control root. The initial control root is `/_private-tunnel`; it is not seeded from an environment variable. Keep the generated Nginx routes and client URLs in sync with changes.

Supplied legacy tokens require 32–4096 visible ASCII characters without whitespace and reject known placeholder prefixes. Invalid nonempty environment tokens prevent startup even if a database already has a token. A bad stored legacy token leaves administrator sign-in available but blocks tunnel authentication until fixed. Normal individual keys are generated by the server; do not invent them by filling `TUNNEL_TOKEN`.

## Upgrades

Back up state first and preserve the original until the new version is verified. The steps below explain changes, not permission to delete an existing database.

- **1.0 → 1.1:** set `DB_PROVIDER=mysql` explicitly if that was the old backend. Keep internal listeners private, regenerate reverse-proxy routes, move away from query-string credentials, and remove obsolete TCP range variables. Do not let a new default silently create an empty SQLite installation.
- **1.2 individual keys:** issue separate keys and create/select matching profiles. Host reservations belonging to a legacy shared identity are not automatically transferred to an unrelated new key. Rotation keeps the key ID and reservations; replacement with a newly issued key changes ownership.
- **1.3 startup and Termux:** the checked-in standalone client supports Node-only installations. Install each boot target explicitly, and reinstall its snapshot after changing its key or runtime.
- **1.4 devices:** existing desktop keys keep their old registry shape. Creating a device key adds `type` and a visitor-secret hash to `client-keys.json`. Older servers reject unknown fields; take a consistent backup before creating device keys. Downgrade using a compatible pre-device registry/database backup rather than stripping fields from live state. Board firmware needs a device key; existing desktop clients do not need to switch protocols.

- **1.4.1 device web login:** requests retain their real content type, and Settings can disable the visitor prompt per device key. Existing keys remain protected until explicitly changed. Saving this policy adds `visitorAuth` to the registry; back up first because 1.4.0 does not understand that field. Policy changes do not rotate secrets or require a new board configuration.
- **1.4.2 idle TCP:** update both server and client to remove the previous fixed five-minute idle cut-off. Reinstall boot jobs after replacing the client so their saved runtime copy is updated too. Existing TCP sessions are interrupted by job replacement; reconnect using the newly reported address. `TCP_IDLE_TIMEOUT_MS=0` keeps healthy idle sessions open by default.

Legacy administrator SHA-256 password sign-in upgrades storage to scrypt when used before **2027-01-01 UTC**. After that cutoff legacy-hash sign-in is rejected. Upgrade and rotate the administrator password before the deadline; keep bootstrap and recovery material private.
